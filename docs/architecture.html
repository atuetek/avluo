AVLUO · APP ARCHITEKTUR · MULTI-TENANT

Stack: Angular 19 + NestJS + PostgreSQL 16 (Wiederverwendung aus organize4u / sm-display)

Strikt isolierte Tenants pro Siedlung · 2000 Mitglieder pro Kooperatif · i18n TR/EN/DE

WAS AVLUO ANDERS MACHT

  • Strikte Tenant-Isolation – Jede Siedlung ist ein eigener Datenraum, kein Cross-Tenant-Lookup möglich. PostgreSQL Row-Level-Security als letzte Verteidigungslinie.
  • Subdomain-Routing – akici-mah.avluo.app für Siedlung 1, cinarli.avluo.app für Siedlung 2. User tippt seine Siedlung, nicht „avluo + Siedlungsname".
  • Trilingual von Tag 1 – User-Content (Posts) mehrsprachig, UI hardcoded trilingual. Eigentümer können in ihrer Sprache posten, andere lesen in ihrer.
  • Notfall-First – Erdbeben-Button broadcastet an ALLE Mitglieder einer Siedlung in 5 Sekunden, mit SMS-Fallback wenn Internet down.
  • Wiederverwendungsgrad ~80% – gleicher Stack wie organize4u + sm-display, alle Patterns übernehmbar.

BACKEND (NESTJS)

  • 11 Microservices statt 6 – Multi-Tenant braucht mehr Spezialisierung.
  • Tenant Service ist neu: verwaltet Kooperatif-Lifecycle, Subdomain-Mapping, Isolation-Garantien.
  • Emergency Service ist neu: separater Service wegen SLAs (99.99% Uptime) und SMS-Bypass.
  • Polling (statt WebSocket) in Phase 1 – 2000 User pro Tenant × 100 Tenants = 200.000 Connections, das skaliert nicht. Polling alle 10s reicht für Timeline, spart 90% Server-Kosten.
  • JWT mit tenant_id – Token ist an Tenant gebunden, kann nicht für anderen Tenant benutzt werden.

DATA LAYER

  • Row-Level-Security (RLS) in PostgreSQL: jede Query muss explizit tenant_id = current_setting('app.tenant_id') matchen. Verhindert Daten-Leaks selbst bei Bug im Service-Code.
  • Shared Schema, logische Trennung – nicht Schema-per-Tenant (würde bei 100 Tenants unhandlich), nicht DB-per-Tenant (würde Hosting teuer). RLS ist Sweet-Spot.
  • MinIO Buckets pro Tenant – absolute physische Trennung auf Storage-Ebene, DSGVO-konform.
  • MeiliSearch pro Tenant – jede Siedlung ihr eigener Search-Index, kein Cross-Index-Leak.
  • NATS Topics – tenant.{id}.events.posts statt events.posts, garantiert topic-level Isolation.

EXTERNAL / DEVOPS

  • Cloudflare Pro – Custom-Hostnames für Subdomain-Mapping pro Tenant, eingebauter DDoS-Schutz.
  • Hetzner (DE) – DSGVO-konformes Hosting, eine VM pro Service-Tier (App, DB, Cache, Storage), nicht pro Tenant.
  • Twilio + Netgsm (TR) – Twilio für internationale SMS, Netgsm für TR-Lokaltarif. Notfall-Broadcast nutzt beide parallel.
  • Brevo – Email mit Multi-Language-Templates, EU-DSGVO-konform.
  • Sentry + PostHog – Error-Tracking + Product-Analytics, beide self-hosted-Optionen verfügbar.

PHASING (EMPFEHLUNG)

  • Phase 1 (MVP, 8–10 Wo) – PWA + 1 Tenant + manuelle Migration der ersten Siedlung. Posts, DMs, Veranstaltungen, Umfragen, Notfall. Polling.
  • Phase 2 (6 Wo) – Multi-Tenant-Support, Tenant-Onboarding-Flow, Yönetim-Panel. WhatsApp-Bot. Subdomain-Mapping.
  • Phase 3 (6 Wo) – iOS/Android Native App, Push-Notifications, Live-Timeline via WebSocket. Analytics-Dashboard.
  • Skalierung – bei >50 Tenants: Read-Replicas, separate DB für Search-Index, CDN für Media.
